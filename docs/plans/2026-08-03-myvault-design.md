# myvault 设计文档

日期：2026-08-03
状态：v0.1 原型已落地

## 背景与目标

个人收藏库：乐高、唱片、书籍、电影。最终形态为个人 blog 网页（主），
未来可能投影为小程序或 Notion 视图（辅）。第一原则是**数据主权**：
任何平台倒闭/改版都不能带走数据。

## 核心决策

### 1. 数据与展示解耦（路线 A）

- 数据层：Git 仓库中的 Markdown 文件，一件藏品一个文件，
  YAML frontmatter 存结构化字段，正文存自由笔记。
- 展示层：静态网站，由零依赖 Node 脚本（`scripts/build.js`）生成。
- 否决路线 B（Notion 做库）：数据主权让渡、API rate limit、深度定制受限。
- 否决路线 C（自建 DB + Web App）：维护成本高，个人项目易烂尾。

### 2. 零依赖构建器

整个生成器 ~400 行、只用 Node 标准库：
- 符合"防御性工程"审美——完全透明、无魔法、无 `node_modules` 黑盒。
- Cloudflare Pages 构建命令就是 `node scripts/build.js`，永远可用。
- 牺牲：无热更新、无主题生态。可接受——个人站点一年重构不了几次。

### 3. 物理化中间态

构建时额外输出 `dist/data.json`（全量藏品数据）。
它是所有未来投影（小程序、CSV 导出给 Excel 透视、统计看板）的统一数据源。

### 4. 录入摩擦最小化（下一阶段重点）

系统存亡取决于录入成本。目标管线：
扫码/报编号 → 调元数据 API（Rebrickable/Discogs/TMDB/豆瓣）→
自动生成 frontmatter → 人只写笔记。

### 5. 隐私边界

`private: true` 的条目不进入任何构建产物。
敏感字段（如入手价）建议写入 private 条目或独立文件。

## 页面结构

- `/index.html` — 首页：馆藏统计 + 最近入库
- `/{type}/index.html` — 分类页：卡片网格
- `/{type}/{slug}.html` — 详情页：左元数据表 + 右笔记正文

## 错误处理

- frontmatter 解析失败：按无 frontmatter 处理（正文全渲染），不中断构建。
- 缺失字段：元数据表跳过该行，卡片副标题自动忽略空值。
- `private: true`：静默跳过。

## 验证

- v0.1：8 件示例藏品，13 个页面，构建 < 400ms，浏览器视觉验证通过。
